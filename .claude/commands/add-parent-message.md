**대상**: $ARGUMENTS

🔴 **학부모 발송은 되돌릴 수 없다.** 이 저장소에서 가장 사고 비용이 큰 작업이다. 아래를 순서대로 밟는다.

## 0. 먼저 읽는다 (건너뛰지 마라)

- `wiki/patterns/alimtalk-send.md` — 발송 함수와 금지 사항
- `wiki/entities/solapi-facts.md` — 승인된 템플릿 목록. **새로 만들기 전에 이미 있는지 본다**
- `wiki/pitfalls/solapi-sender-typo.md` — 발신번호 사고에서 나온 규칙
- 해당 시스템 페이지의 **"학부모에게 나가는 것"** 절 — 원장이 확정한 내용이 있다

## 1. 이 메시지를 정말 보내야 하는지 확인한다

🔴 **원장이 이미 반려한 알림이 여러 개 있다.** 제안하기 전에 확인한다:

- 결석 접수 확인, 지각·조퇴 접수 알림톡, 보강 전날 리마인더 → **전부 폐기됨** (`wiki/systems/absence-notice.md`)
- "한 건으로 여러 통 받는 것을 원하지 않는다"가 원장의 원칙이다

이미 반려된 것이면 **거기서 멈추고 사용자에게 알린다.** 다시 제안하지 마라.

## 2. 템플릿

1. 기존 승인 템플릿으로 되는지 먼저 본다 (`solapi-facts`)
2. 안 되면 카카오 심사에 새로 올린다 — **시간이 걸린다. 코드보다 먼저 시작한다**
3. 템플릿 ID는 **Render 환경변수**에 넣는다. 코드에 박지 마라
4. 없을 때 발송만 건너뛰고 서버는 뜨도록 폴백 `''`을 둔다 (`api/index.js:331` 참고)

## 3. 코드

- `sendAlimtalk(to, templateId, variables)` — `api/index.js:368`
- 🔴 **변수명을 템플릿 등록값과 글자 단위로 맞춘다.** 어긋나면 거부되거나 `#{이름}`이 그대로 학부모 폰에 찍힌다
- 🔴 **변수를 빈 값으로 보내지 마라**
- 🔴 **문자 폴백 금지** (`disableSms: true`). 원장 확정
- 발송 판정은 체크박스가 아니라 **`확정발송일시` 같은 타임스탬프**로 한다 — 체크를 껐다 켜도 두 번 안 나가게
- 크론 루프 안이면 개별 `try/catch` — 한 명 실패로 나머지가 막히면 안 된다
- 실패는 반드시 **카카오워크로** 통지한다. 🔴 실패 통지를 실패하는 경로로 보내지 마라

## 4. 검증 (제일 중요)

1. **실제 번호로 1건 보낸다**
2. **`/messages`에서 보낸 본문을 되읽어 확인한다** — 변수가 제대로 치환됐는지 눈으로 본다
3. `statusCode === '4000'`인지 확인한다. 그 외는 접수만 되고 안 간 것이다
