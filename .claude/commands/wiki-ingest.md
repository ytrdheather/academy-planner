`wiki/SCHEMA.md`의 **ingest** 절차를 따라 다음을 위키에 흡수하라.

**대상**: $ARGUMENTS
(비어 있으면 **이번 세션에서 실제로 바꾸거나 알아낸 것**을 대상으로 삼는다. `git diff`와 대화 내용을 근거로.)

## 절차

1. 대상을 읽는다. 코드면 실제 파일을, 사실이면 근거를 확인한다.
2. **`wiki/index.md`를 먼저 읽고 들어갈 자리를 찾는다.** 기존 페이지에 자리가 있으면 **새 페이지를 만들지 말고 갱신**한다.
3. 자리가 없을 때만 새 페이지를 만든다. 디렉토리는 "이게 무슨 질문에 답하나"로 고른다:
   `patterns/` 재사용 코드 · `entities/` 사물 · `systems/` 업무 흐름 · `decisions/` 왜 · `pitfalls/` 아팠던 것
4. **영향 범위를 넓게 본다.** 하나를 바꾸면 보통 여러 페이지가 흔들린다 — 크론을 바꿨으면 `entities/cron-jobs`와 해당 `systems/*` 둘 다.
5. frontmatter를 정확히 채운다. 특히:
   - `source:` — `api/index.js:147-186` 형태로 **실제 라인**을 확인해서
   - `status:` — 코드를 눈으로 봤으면 `verified`, 문서·기억 기반이면 `inferred`
   - `updated:` — 오늘 날짜
6. 관련 페이지로 `[[링크]]`를 건다. 아직 없는 페이지를 가리켜도 된다.
7. 새 페이지를 만들었으면 `wiki/index.md`에 한 줄 추가한다. 미작성 링크가 생겼으면 index의 "미작성" 표에 넣는다.
8. `wiki/log.md` 맨 아래에 추가한다:
   ```
   ## [YYYY-MM-DD] ingest | 한 줄 요약
   ```

## 규칙

- **페이지당 40줄 이하.** 길어지면 쪼갠다. 코드 스니펫은 5줄 이내, 나머지는 `file:line`으로 가리킨다.
- 원본을 복사하지 마라. 인용해라. 위키는 지도지 영토가 아니다.
- 파일명·`id`·`tags`는 영어 kebab-case, 본문은 한국어, 도메인 용어(노션 속성명 등)는 한국어 원문 그대로.
- 코드는 읽기만 하고 **고치지 않는다.**

마지막에 **무엇을 새로 만들고 무엇을 갱신했는지 목록으로** 보고하라.
