## 한 줄

그날 등원 예정 학생 **전원**의 숙제를 11시 크론이 자동 생성한다. 교재 커서(현재유닛)를 진도량만큼 밀어 문구를 만드는 구조.

## 흐름 (전부 KST 크론)

| 시각 | 무엇 |
|---|---|
| 10:20 | `generateDailyReports()` — 그날 수강요일 재원생의 학습진도 페이지 생성 (멱등) |
| 11:00 | `autoGenerateHomework()` — 등원 예정 학생 전원의 숙제 생성·기록 |
| 22:00 | `데일리리포트URL` 기록 |

## 11시 크론의 핵심 설계 결정 — 출석 여부를 보지 않는다

11시엔 아직 아무도 출석 체크 전이라, 출석을 요구하면 **아무것도 생성되지 않는다.** 대신 네 가지로 거른다:

- 결석사유가 **이미 적힌** 학생 제외 (미리 아는 결석은 11시 전에 적어두면 아예 안 나감)
- 학습상태가 `정상`이 아닌 학생 제외 (병결·여행·휴가·휴원)
- 이미 문구가 있는 과목은 건너뜀 → **멱등, 수기 수정분을 덮어쓰지 않음**
- 정지 기간(공휴일·방학, `PAUSE_DB_ID`)이면 통째로 건너뜀 — **전역 킬스위치**

`computeHomeworkProposals({ dateStr, onlyName, requireAttendance })`가 미리보기 화면과 크론이 **공유하는 계산부**다. `requireAttendance`는 수동 전체 생성일 때만 `true`.

**2026-08-22부터 `출석`의 주인이 바뀌었다** — 선생님이 찍던 것을 학생이 플래너를 저장할 때 서버가 켠다. 수동 전체 생성(`requireAttendance:true`)의 대상이 "플래너를 저장한 아이"가 된다 → [[arrival-alert]]

## 결석 자동 롤백

11시에 전원 생성하므로 결석자에게도 숙제가 나간다. 이를 **결석사유를 입력하는 순간** 자동 정리한다 — `rollbackHomeworkForAbsence()`. 그날 문구를 지우고 커서를 직전배정량만큼 되돌린 뒤 **직전배정량=0**으로 두어 이중 롤백을 막는다.

선생님은 하던 대로 결석사유만 적으면 되고 버튼을 따로 누를 필요가 없다. **이게 채택 이유다.** 사유를 지우는 건 아무 동작 안 한다(다시 만들려면 개인 🔮).

## 계약 — 버튼 2종의 역할 구분 (헷갈리기 쉬움)

| | 하는 일 |
|---|---|
| **`<<` `>>` 트랙 이동** | 오늘 낸 숙제를 한 묶음 뒤/앞으로. **문구와 커서를 함께** 다시 쓴다 → [[homework-track-move]] |
| **🔮 생성(개인)** | 숙제가 **없는** 학생에게 새로 만듦. 늦게 온 학생·빠진 학생용 |

**`<<` `>>` 는 있는 걸 고치고, 🔮 는 없는 걸 만든다.** 옛 `↩ 미룸`·`→ 전진` 은 커서를 기준으로 움직여서 한 칸 건너뛰거나(11→13) 문구를 안 고쳐 아무 일도 안 일어난 것처럼 보였다 → 2026-08-14 에 라우트째 없앴다. 여러 칸을 옮겨야 하면 **진도 관리 탭에서 유닛 숫자를 직접 수정**하는 게 빠르다.

## 과목이 생성에서 빠지는 3가지

**교재 관계가 비어 있으면 조용히 제외**(그 과목을 안 하는 학생 = 정상). 교재가 있는데 못 만드는 경우만 `blocked: true`로 이유와 함께 내려보내고, 미리보기에서 체크박스를 잠가 **경고문이 숙제칸에 기록되지 않게** 막는다.

| 상태 | 표시 | 색 |
|---|---|---|
| 진도량 빈칸 | ⚠ 진도량 미설정 | 빨강 — 고쳐야 함 |
| 커서가 교재 끝을 넘음 | ⚠ 교재 끝(현재유닛 N) | 빨강 — 고쳐야 함 |
| 진도방식 `직접입력` | ✍ 직접 입력 과목 | 회색 — **정상 운영** |

**이 구분이 왜 필요했나**: 예전엔 진도량이 비면 `continue`로 삼켜 그 과목이 화면에서 사라졌다. 선생님은 🔮를 몇 번 눌러도 "숙제 없음"만 봐서 원인을 알 수 없었다(2026-07-28, 재원 84명 중 11건). 반대로 경고만 넣으면 정량을 안 쓰는 학생이 매번 오류처럼 보인다. 그래서 둘을 나눴다.

## 함정

- 교재 끝이 5회 앞으로 다가오면 숙제칸·진도 관리 탭에 `5회`…`last` 배지가 뜬다 → [[homework-track-move]]
- 🔴 **교재를 바꿔도 현재유닛(커서)은 그대로 남는다.** `saveTextbook`이 커서를 안 건드린다. 이전 책을 60까지 끝낸 학생에게 새 책을 주면 커서 60이 남아 "⚠ 교재 끝"이 계속 뜬다. 자동 리셋 여부는 **미결**(중간에 갈아타는 경우가 있어 강제하지 않음).
- **진도 관리 탭에서 유닛 숫자만 고치면 "다음 생성"부터 반영된다.** 오늘 이미 나간 문구는 안 바뀐다 → → 버튼을 쓰거나 숙제칸을 직접 수정.
- 교재 유닛 DB의 `순번`과 교재의 실제 "Unit N" 표기가 다를 수 있다. **커서는 순번 기준.**
