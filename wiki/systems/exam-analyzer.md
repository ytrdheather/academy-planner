## 한 줄

시험지 이미지·PDF를 Claude vision으로 분석해 문항별 정답지를 만들고(원장 전용), 그 정답지로 학생 답안을 채점해 리포트까지 낸다.

## 흐름

```
[정답지 만들기]  /exam-analyzer → 이미지·PDF 업로드(최대 10장, 32MB)
   → Claude가 문항별 유형/출제범위/문법포인트/배점/난이도/정답 추출
   → 편집표에서 선생님이 수정 → 저장
   → EXAM_DB(시험 1개=1행) + QUESTION_DB(문항 1개=1행, relation)

[채점]  /student-grader → 저장된 시험 선택 + 학생 이름 입력 + 답안 업로드
   → Claude는 학생 답만 읽음 → 코드가 정답지와 대조
   → 편집 가능한 정오표(라이브 점수) → 저장
   → STUDENT_RESULT_DB(학생 1명=1행) + STUDENT_ANSWER_DB(학생×문항=1행)

[보기]  /results-viewer (시험별·학생별 탭)  /student-report?resultId= (학부모용 리포트 카드 → PNG 저장·인쇄)
```

**전부 원장 전용** — `requireOwner` (`loginId === 'manager'`).

## 계약

- 🔴 **학생 이름·학교·학년은 손글씨 인식을 하지 않는다.** 선생님이 직접 입력·선택한다(오인식하면 정답지 매칭이 깨진다).
- 🔴 **서술형은 자동채점하지 않는다.** 학생답을 옮겨적어 모범답안 옆에 보여주고 선생님이 O/X를 고른다(초기 `verdict='채점대기'`). 점수·취약유형·리포트는 **선생님이 검토한 최종 verdict로 재계산**한다.
- 객관식 대조는 `normalizeAnswer`(①②③④⑤→1~5, 공백 제거, 소문자).
- **출제범위 4종**(교과서본문·외부지문·대화문·학습지)은 **이미지만으로 AI가 구분할 수 없어 선생님이 드롭다운에서 고르는 것이 의도된 설계다.** 자동화하려 하지 마라.
- **문항별 한 줄 저장 구조를 JSON blob으로 되돌리지 마라.** 처음엔 `문항데이터` 한 칸에 JSON을 넣었는데 노션에서 안 읽혀서 바꿨다. 문항 행이 있어야 "이 학생이 여러 시험에서 관계대명사를 반복 오답" 같은 누적 분석이 된다.
- 지문이 안 잡히는 독해문항은 정답이 틀릴 수 있다 → 편집표에서 수정하는 게 정상 운영이다.
- **학부모 링크** (2026-10-02): 리포트 화면 [📤 학부모 공개] → 그 순간 화면 데이터(원장이 고친 문장 포함)를 결과행 `학부모리포트` 칸에 JSON 사본으로 저장 + `공개일시` 기록 → [🔗 링크 복사]로 `/exam-report?id=결과ID` 를 카톡으로 보낸다. 학부모 화면은 **사본만** 읽는다(노션 1회, AI 호출 0, 로그인 없음). `공개일시`가 비면 링크가 "준비 중"으로 뜬다. 🔴 **재채점하면 공개가 풀린다**(점수가 바뀌었을 수 있으니 원장이 다시 확인하고 공개). 공개 뒤에 문장을 고쳤으면 [다시 공개]해야 링크에 반영된다. 테스트 `test/exam-report.test.mjs`.
- **`/student-report`는 학부모용 카드다** (2026-10-02). 색은 대시보드 팔레트 + 리디튜드 로고 → [[readiplan-brand]]. 원장이 [🖼️ 이미지로 저장]으로 PNG를 받아 **카톡으로 직접 보낸다** — 자동 발송 없음. 카드: 점수·선택형/서술형 분리·(중학교만) 성취수준 A~E 막대 → 실점 문항(학생 답→정답, 오답 요인) → 핵심 진단 → 선생님 코멘트 → 대처 방안. 문장은 화면에서 눌러 고칠 수 있고 **고친 내용은 [학부모 공개] 때 사본에 함께 저장된다**(공개 전엔 이미지에만 반영).
- 진단·오답 요인·대처 방안은 Gemini JSON 1회 생성 → 결과행 `리포트AI` 칸에 JSON으로 캐시(2000자 조각 나눠 씀). **재채점 시 `AI코멘트`와 함께 비운다.** AI 실패 시 `buildParentReportFallback`. 오답 요인은 문제 원문 없이 유형·문법포인트·답만 보고 쓰는 **추정**이라 리포트에도 그렇게 적는다.
- **시험 기간 학습 브리핑** (2026-10-02): 채점일 기준 **최근 30일** 진도 기록(수업 횟수·숙제 수행률·단어 평균)과 선생님 일일 코멘트(`❤ Today's Notice!`)를 모아 잘 대응한 점 / 아쉬웠던 점 / 학생이 주도적으로 개선할 점 / 학원 지도 포인트 네 칸을 쓴다. 같은 Gemini 호출에서 만들어 `리포트AI.attitude`에 함께 캐시한다. 진도 읽기는 월간 리포트의 `loadStudyPeriod`(`monthlyReportModule.js` export)를 **주입받아 쓴다 — 복사하지 마라** → [[monthly-report]]. 진도 기록이 없거나 AI가 실패하면 칸을 숨긴다(폴백은 태도를 지어내지 않는다). 시험일은 저장하지 않아 채점일을 끝으로 잡는다 — 채점이 시험 후 한참 뒤면 기간이 밀린다.
- **난이도(상/중/하)는 리포트 코멘트에 쓰인다** (2026-10-02). 분석 때 AI가 매긴 `난이도`를 `loadAnswerKey`가 읽고 `summarizeByDifficulty`가 난이도별 정오를 요약해 프롬프트에 넣는다 → 상 난이도 정답은 칭찬, 하 난이도 오답은 원인(실수·확인 부족·암기 누락) 추정 + 개선법, 하·중 실점 보완책. 시험에 난이도가 없으면 이 지시는 빠진다. 2026-10-02 이전엔 저장만 되고 아무 데도 안 쓰였다.
- **속도 (2026-10-03, 처음 열 때 8~10초 → 해소):** 리포트 생성은 `buildReport()` 한 곳(화면 라우트와 미리 만들기가 공유). 노션 읽기(결과+답안 / 시험+정답지)와 Gemini 두 번(종합 코멘트 ∥ 진도 읽기→리포트 문구)을 **동시에** 돌리고, AI 문구 저장은 **PATCH 한 번**으로 묶어 화면을 띄운 뒤 한다. 칸이 이미 있으면 DB 스키마 PATCH 를 건너뛴다.
- **미리 만들기 `warmReport`:** 원장이 채점을 저장하면(`save-student-result`) 뒤에서 리포트 문구를 만들어 캐시해 둔다 → 열 때 1~2초. 재채점 후에도 한 명씩 다시 만든다. 🔴 막 만든 노션 행은 검색에 늦게 잡힌다 — **답안 수가 저장한 문항 수와 맞을 때만** 만든다(`expectedCount`, 3초 간격 4번). 덜 읽힌 채로 캐시하면 틀린 리포트가 굳는다. 서술형 `채점대기`가 남았으면 만들지 않는다. 학생 셀프 제출은 미리 만들지 않는다.
- Render 로그에 `[시험 리포트] 이름 1234ms (캐시|AI 생성|AI 실패·규칙 문구)` 가 찍힌다 — 느리다는 말이 나오면 여기부터 본다.
- 🔴 **리포트 프롬프트를 바꾸면 `REPORT_PROMPT_VERSION`을 올려라.** `리포트AI.v`가 다르면 `AI코멘트`·`리포트AI` 캐시를 둘 다 버리고 새로 만든다. 안 올리면 이미 열어 본 학생은 옛 문구가 계속 나온다.
- **학생 리포트 문장은 규칙 + AI 혼합.** 대책은 규칙 기반 `TYPE_ADVICE`/`SOURCE_ADVICE` 매핑, 종합 코멘트만 Gemini가 쓰고 **실패하면 규칙 폴백**.

## 리디테스트 대비 범위 → 코멘트 (2026-10-02)

원장 확정: **리디테스트가 분석한 포인트로 동형 모의고사(보통 5세트)를 만들어 그 학교 학생이 전부 풀었다** → "분석한 포인트 = 학생이 연습한 포인트"로 본다. "학생이 풀었는지 모른다" 같은 단서를 달지 마라. 대비 자료는 결국 모든 학교에 생긴다.

- `data/readitest-coverage.json`(리디테스트 `tools/export_readiplan_coverage.py` 산출물을 복사)을 `findCoverage`가 학교(○○중학교→○○중)·학년·연도·학기·회차로 찾는다. 파일·행이 없으면 조용히 빠진다.
- 찾으면 프롬프트에 `[학원 내신 대비]`를 넣는다 → 틀린 문법이 대비 포인트면 "동형으로 반복해 풀어 본 포인트인데 실전에서 숙지가 미흡" + 학원이 이어서 할 일, 대비 밖이면 "학교가 새롭게 낸 부분 → 다음 대비 자료에 반영". 포인트 표기가 달라도 같은 문법이면 AI가 같은 것으로 본다(코드 통일을 기다리지 않는다).
- **현재 파일(2026-10-02 생성):** 중2 2026-2학기 **중간** 4개교만 — 영덕(동형 3세트·4포인트)·영일(5·5)·청명(5·5)·태장(5·6). 포인트는 목적격 관계대명사·so~that 류·지각동사·used to 공통 + 학교별 전치사/-ing 구별. 중1·기말은 아직 없다.
- 🔴 파일은 **시험 시즌마다 리디테스트에서 다시 뽑아 복사하고 커밋·배포**해야 Render 에 반영된다. 뽑는 법: Readitest 에서 `python tools/export_readiplan_coverage.py` → `data/export/readiplan_coverage.json` 을 이 저장소 `data/readitest-coverage.json` 으로 복사. 내보낼 시험 목록은 그 스크립트의 `EXAMS` 에 손으로 적혀 있다(새 시험이면 거기 추가). 리포트 문구를 바꾸면 `REPORT_PROMPT_VERSION`(지금 3)을 올린다.

## 리디테스트 연동 (조사만, 미착수)

별도 저장소 `Desktop/Readitest`(기출 분석·동형 모의고사, Supabase)의 데이터를 리포트에 쓰려는 계획. 조사 보고서: `Readitest/docs/리디플랜_연동_데이터조사.md` (2026-10-02, 워크트리 `festive-morse-131fe5` 에서 작성 — 원본 main 에 아직 안 합쳐졌을 수 있다).

- 🔴 **지금 데이터로 "이 학교 단골 포인트"라고 쓰지 마라.** `school_grammar_map` 기출 근거는 학교당 시험 **1회분**(2026-1 기말, 중2)뿐이라 말할 수 있는 건 "지난 기말에 낸 포인트"까지다. 4개교 공통은 수동태·분사뿐. 게다가 적재 스크립트가 (학교, 코드)로 중복을 걸러 **2회째 관측을 버린다** — 리디테스트 쪽에서 먼저 고쳐야 한다.
- 시험일 `exam.exam_date`는 **지난 중2 시험 5건**뿐. 다가오는 시험·중1은 DB에 없다(블루프린트 파일에만).
- 어법 포인트 코드 38개(승인 31) — 중학교용으로 쓸 만하다. 분석기의 자유 텍스트 문법포인트를 **"코드 선택 + 목록에 없음(자유 텍스트)"**으로 바꾸는 게 연결의 첫 단계. 목록을 리디플랜이 독단으로 늘리지 마라(두 시스템 코드가 갈린다).
- 대비 자료(동형 24세트·어법 드릴 614문항)는 **DB가 아니라 파일**에 있다. 드릴만 포인트 코드가 붙어 있다.
- 읽기 경로: 보고서용 뷰 2개(`report_school_grammar`·`report_exam_schedule`)만 anon 에 select 허용하는 1안 권장. **`service_role` 키를 리디플랜에 넣지 마라.** 키는 서버 `.env`에만. 뷰는 아직 안 만들었다(원장 확인 대기).
- 학교 이름: 리디테스트는 "영덕중" 표기. 리디플랜 쪽에서 공백 제거 + 끝 "중학교"→"중"으로 정규화, 4개교 밖·고등학교는 매칭하지 않는다.

## 남은 일 / 확인 필요

- **Render 환경변수 4개가 다 등록됐는지** — 빠지면 500. `EXAM_DB_ID`·`ANTHROPIC_API_KEY`는 등록 확인됨.
- **실제 학생 답안으로 `grade-student` 실사용 테스트가 아직 없다** — 손글씨·마킹 인식률과 서술형 옮겨적기 품질 미검증.
- 후보: 결과 CSV/PDF 내보내기, 반 전체 통계(학원 평균·최다 오답 — 2026-10-02 원장이 보류).
- **2단계(미착수):** 실점 문항 카드에 시험지 해당 문제 사진 잘라 넣기 — 지금은 시험지 이미지를 저장하지 않아 문항 위치 추출+보관부터 필요. 알림톡 링크 자동 발송 — 로그인 없이 열리는 링크 + 카카오 템플릿 심사 필요([[alimtalk-send]]).
