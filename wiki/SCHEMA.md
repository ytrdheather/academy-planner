# 위키 스키마

이 위키는 Karpathy의 LLM-wiki 패턴을 따른다. 핵심 발상: **매번 원본을 다시 뒤지지 말고(RAG), 원본에서 뽑아낸 이해를 쌓아 올린 인공물을 유지한다.** 지식베이스 유지의 힘든 부분은 읽고 생각하는 게 아니라 장부 정리(bookkeeping)이고, 그건 LLM이 잘한다.

## 세 개의 층

| 층 | 무엇 | 누가 쓰나 |
|---|---|---|
| **raw source** | `api/`, `public/`, `docs/*.md`, `.env.example`, git 히스토리, 메모리 파일 | 사람 (또는 원래 있던 것) |
| **wiki** | `wiki/**/*.md` | Claude가 전적으로 소유. 사람이 직접 안 고쳐도 됨 |
| **schema** | 이 파일 + 루트 `CLAUDE.md` | 규칙. 둘이 합의해서 진화시킴 |

**위키는 원본을 복사하지 않는다. 인용한다.** 코드가 진실이고 위키는 지도다. 지도가 틀렸으면 지도를 고친다.

## 디렉토리

```
wiki/
  SCHEMA.md      이 파일
  index.md       전체 카탈로그. 검색 진입점. 페이지당 1줄
  log.md         append-only 작업 이력
  patterns/      재사용 코드 자산 — "이걸 또 짜지 마라"
  entities/      구체적 사물 — Notion DB, 환경변수, 크론, 라우트, 화면, 외부 서비스
  systems/       업무 시스템별 동작 계약 — "이건 이렇게 돌아간다"
  decisions/     왜 그렇게 골랐나 (ADR)
  pitfalls/      밟은 지뢰와 거기서 나온 규칙
```

## 페이지 포맷

모든 페이지는 이 frontmatter로 시작한다:

```yaml
---
id: notion-prop-read          # 파일명과 동일. kebab-case 영어
title: 노션 속성 값 읽기        # 한국어
type: pattern                 # system | module | entity | pattern | decision | pitfall
status: verified              # verified | inferred | stale
source: api/index.js:149-188  # 근거 위치
updated: 2026-08-15
tags: [notion, helper]        # 영어 소문자
---
```

### `status` — 이 위키의 신뢰 장치

| 값 | 뜻 |
|---|---|
| `verified` | 해당 코드를 실제로 열어보고 썼다 |
| `inferred` | 문서·기억·설계안 기반. 코드로 대조하지 않았다. **믿고 행동하기 전에 확인할 것** |
| `stale` | 근거가 바뀐 걸 알지만 아직 못 고쳤다 |

`grep -rl "status: inferred" wiki/` 하면 검증 대기 목록이 나온다.

### 언어

파일명·`id`·`tags`·코드 식별자는 영어. 설명 본문은 한국어. 도메인 용어(담임 롤업, 교재비 승인 등)는 노션 실제 속성명 그대로 한국어를 쓴다 — 번역하면 코드와 어긋난다.

### 본문 섹션 (타입별 고정)

| type | 섹션 |
|---|---|
| `pattern` | 문제 / 해법 / 쓰는 법 / 안 되는 경우 |
| `entity` | 정체 / 표 / 쓰는 곳 / 주의 |
| `system` | 한 줄 / 흐름 / **계약(건드리면 안 되는 것)** / 관련 코드 / 관련 페이지 |
| `decision` | 결정 / 배경 / 기각한 대안 / 재검토 조건 |
| `pitfall` | 증상 / 원인 / 고친 방법 / **규칙** |

### 길이

**페이지당 40줄 이하를 목표로 한다.** 길어지면 쪼갠다. 위키의 목적은 토큰 절약이다 — 페이지가 원본 코드만큼 길어지면 존재 이유가 없다. 코드 스니펫은 5줄 이내, 나머지는 `file:line`으로 가리킨다.

### 링크

`[[page-id]]` 로 쓴다. 아직 없는 페이지를 가리켜도 된다 — 그건 오류가 아니라 "이건 언젠가 써야 한다"는 표시다. 링크를 아끼지 마라.

## 세 가지 연산

### ingest — 새 것을 흡수한다

무엇을 ingest 하나: 새로 짠 코드, 방금 고친 버그, 읽은 문서, 사용자가 알려준 사실, 실제 운영에서 관찰한 것.

1. 대상을 읽는다
2. **먼저 `index.md`를 보고 기존 페이지에 들어갈 자리가 있는지 찾는다.** 있으면 새 페이지 만들지 말고 갱신
3. 자리가 없을 때만 새 페이지를 만든다. 어느 디렉토리인지는 "이게 무슨 질문에 답하나"로 정한다 — 재사용 코드면 `patterns/`, 사물이면 `entities/`, 업무 흐름이면 `systems/`, 왜냐면 `decisions/`, 아팠으면 `pitfalls/`
4. **영향 범위를 넓게 본다.** 하나를 바꾸면 보통 여러 페이지가 흔들린다 — 크론을 바꿨으면 `entities/cron-jobs` 와 해당 `systems/*` 둘 다
5. 새 페이지를 만들었으면 `index.md`에 한 줄 추가
6. `log.md`에 한 줄 추가

`/wiki-ingest` 슬래시 커맨드가 이 절차를 수행한다.

### query — 위키에 묻는다

1. `index.md`를 읽는다
2. 관련 있어 보이는 페이지만 연다 (전부 열지 마라)
3. 답한다. 근거를 `wiki/patterns/notion-fetch.md` 또는 `api/index.js:67` 형태로 명시
4. 위키에 답이 없으면 코드를 판다. **그리고 그 결과를 곧바로 ingest 한다** — 같은 걸 두 번 파지 않기 위해서
5. 답이 좋았으면 그 자체를 새 페이지로 환원한다

`/wiki-query` 커맨드.

### lint — 건강검진

주기적으로(또는 큰 작업 뒤에) 돌린다. 점검 항목:

- **끊긴 링크** — `[[id]]` 중 실존 파일이 없는 것
- **고아 페이지** — 아무도 링크 안 하고 `index.md`에도 없는 것
- **`index.md` 누락** — `wiki/*/*.md` 는 있는데 index에 없는 것
- **밀린 `source:`** — `api/index.js:149` 이 실제로 그 함수인지. 코드가 밀리면 라인 번호가 거짓말이 된다
- **`status: inferred`** — 아직 코드로 확인 안 된 페이지 목록
- **모순** — 두 페이지가 같은 사실을 다르게 말하는 것
- **오래된 `updated:`** — 오래됐고 그 사이 코드가 바뀐 것

결과는 사람에게 보고하고 `log.md`에 남긴다. **lint는 자동으로 고치지 않는다** — 보고하고 승인받는다.

`/wiki-lint` 커맨드.

## log.md 포맷

append-only. 한 항목 = 한 줄 헤딩 + 필요하면 짧은 본문.

```
## [2026-08-15] ingest | 크론 표 갱신 — 교재비 발송 21시→20시
```

`op` 는 `ingest` | `query` | `lint` | `bootstrap`. 유닉스 도구로 읽히게 유지:

```bash
grep "^## \[" wiki/log.md | tail -10
```

## 메모리와의 관계

`~/.claude/.../memory/` 는 **자동 로드되는 얕은 층**이다. 세션 시작할 때 무조건 들어오니까 짧아야 한다.
위키는 **필요할 때 여는 깊은 층**이다.

규칙: 메모리에는 "지금 상태 한 줄 + 위키 포인터"만. 상세는 위키로. 같은 사실을 양쪽에 길게 쓰지 마라 — 갈라진다.

## 규모

지금 규모(수십 페이지)에서는 `index.md` 기반 검색으로 충분하다. 수백 페이지를 넘어가면 임베딩 검색을 고민한다. 그 전까지는 index를 잘 유지하는 게 전부다.
