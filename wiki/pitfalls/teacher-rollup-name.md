## 증상

교재비 담당쌤 알림 **14건이 안 나갔다.** 그런데 원장에게는 "담당쌤 미지정"으로 보고됐다 — 담임은 멀쩡히 지정돼 있었다. 더 나빴던 건 **못 보낸 건에도 `교사알림함` 플래그가 올라간 것**이다. 이름만 고쳤으면 그 14건은 영영 묻혔다.

## 원인

두 겹이다.

**① 노션 속성 이름이 바뀌었다.** 교재비 DB의 롤업 이름이 **`담임쌤`**(relation=학생 / prop=담당쌤 / show_original)인데 코드는 `담당쌤`을 읽고 있었다. 2026-08-10엔 맞았고 그 뒤 노션에서 사람이 바꿨다.

**② 없는 속성은 `undefined`라서 "담임이 지정 안 됨"과 구분되지 않았다.** 코드는 둘 다 "담당쌤 없음"으로 처리했다.

## 고친 방법

```js
p['담임쌤'] ?? p['담당쌤']   // 둘 다 받는다
```

그리고 실패를 **세 갈래로 나눴다**:

| 갈래 | 플래그 | 이유 |
|---|---|---|
| **설정 오류**(롤업을 못 읽음) | **안 올림** | 고치면 다음 바퀴에 자동으로 나간다 |
| 담임 미지정 / 카카오워크 ID 없음 | 올림 + 원장 보고 | 사람이 손대야 끝나는 일. 매일 반복하면 소음 |
| 성공 | 올림 | |

## 🔴 규칙

1. **"고치면 되는 실패"에는 완료 플래그를 올리지 마라.** 플래그는 "사람이 손대야 끝나는 일"과 "다음 바퀴에 저절로 될 일"을 구분해야 한다.
2. **노션 속성 이름은 사람이 언제든 바꾼다.** 이름으로 읽는 곳은 없어졌을 때를 대비하라 — `getPropByKeywords`를 쓰거나 `??`로 대안 이름을 받아라 → [[notion-prop-read]]
3. **없는 속성(`undefined`)과 빈 속성(`null`/`''`)을 구분하라.** 이 둘을 같게 처리하면 설정 실수가 데이터 실수로 보고된다.

## 복구 방법

`교사알림함`을 `false`로 되돌리면 다음 바퀴에 다시 나간다. 단 **이미 나간 건까지 되돌리면 중복 발송**이니 실패한 건만 골라서 내릴 것(이름 목록으로 필터링, **dry-run 먼저**).
